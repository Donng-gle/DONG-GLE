# 동글 온보딩 알고리즘 명세서

> 작성일: 2026-07-05
> 버전: v2.0.0
> 관련 API: `GET /onboarding/next`, `POST /onboarding/swipe`, `POST /onboarding/complete`, `POST /onboarding/reset`

---

## 1. 개요

온보딩은 사용자가 앱을 처음 실행했을 때 감성 이미지 카드를 보여주고
좋아요 / 싫어요를 선택하게 하여 **사용자 감성 벡터(user_vector)** 를 생성하는 과정이다.

### 핵심 원칙

- AI는 추천하지 않는다. AI의 역할은 **사진 분석(벡터 생성)** 뿐이다.
- 온보딩의 목적은 사용자가 좋아할 사진을 보여주는 것이 아니라 **취향을 가장 빠르게 파악**하는 것이다.
- 추천은 사용자 벡터와 장소 벡터의 **Cosine Similarity** 로 계산한다.
- 결과 벡터는 **뾰족하게(특정 태그가 두드러지게)** 나와야 한다. 모든 태그가 중간값에 몰리면 개인화 의미가 없다.

## 2. 감성 태그 (7개 확정)

모든 사진과 사용자는 아래 7개 태그의 독립적인 0.0~1.0 점수 벡터를 가진다.

| 태그 | 의미 | AI 판단 기준 (5가지) |
|------|------|----------------------|
| `relaxing` | 여유, 힐링, 자연, 조용함 | 한적함 있음 / 조용한 분위기 있음 / 개방감 있음 / 자연 요소 있음 / 오래 머물고 싶은 분위기 있음 |
| `lively` | 활기, 시장, 축제, 북적임 | 사람 밀집도 높음 / 활동적인 분위기 있음 / 상업적 활기 있음 / 축제·행사 분위기 있음 / 에너지 있는 분위기 있음 |
| `romantic` | 야경, 데이트, 감성 | 감성적인 조명 있음 / 따뜻한 색감 있음 / 아늑한 분위기 있음 / 감성적인 연출 요소 있음 / 특별한 추억을 만들고 싶은 분위기 있음 |
| `local` | 동네감성, 골목, 숨은명소 | 지역 고유의 분위기 있음 / 생활감 있는 공간 있음 / 지역 문화 요소 있음 / 지역만의 개성 있음 / 소박한 분위기 있음 |
| `photogenic` | 사진 찍기 좋은 분위기 | 좋은 사진 구도 있음 / 아름다운 배경 있음 / 매력적인 색감·조명 있음 / 시선을 끄는 포인트 있음 / 사진으로 남기고 싶은 장면 있음 |
| `traditional` | 전통적인, 역사적인, 한국적인 감성 | 전통적인 분위기 있음 / 역사적인 분위기 있음 / 한국적인 감성 있음 / 고즈넉한 분위기 있음 / 문화유산적인 분위기 있음 |
| `modern` | 현대적인, 세련된, 트렌디한 분위기 | 현대적인 분위기 있음 / 도시적인 분위기 있음 / 세련된 분위기 있음 / 트렌디한 분위기 있음 / 감각적인 분위기 있음 |

### 주의사항

- `traditional`과 `modern`은 합이 1이 아닌 **독립적인 점수**로 관리한다.
- 한옥 카페처럼 두 태그가 모두 높은 복합 공간이 존재하기 때문이다.

## 3. 사용자 벡터 초기값

```json
{
  "relaxing":    0.5,
  "lively":      0.5,
  "romantic":    0.5,
  "local":       0.5,
  "photogenic":  0.5,
  "traditional": 0.5,
  "modern":      0.5
}
```

- 모든 태그를 **중립(0.5)** 에서 시작한다.
- 좋아요/싫어요에 따라 각 태그 점수가 올라가거나 내려간다.
- 합이 1이 되도록 정규화하지 않는다. (7개 태그 독립 관리)

## 4. 온보딩 카드 풀 구성 기준

### 필수 조건

```
태그별 대표 카드: 최소 4장 이상 (시드 1장 + 후보 3장 이상)
전체 카드 풀: 최소 35장 이상 권장
카드당 벡터: AI가 사전 분석하여 DB에 저장 (온보딩 런타임에 AI 호출 없음)
```

태그별 카드 수가 부족하면 균형 전략이 무너진다.
예) modern 강한 카드가 2장뿐이면 modern 정보를 충분히 수집 못하고 수렴해버림.

### 시드 카드 (7장)

태그별 대표 이미지 1장씩. 초반 7장에서 모든 태그의 초기 신호를 확보한다.

| 카드 | 대표 태그 | 역할 |
|------|-----------|------|
| 하회마을 | traditional 0.95 | Traditional 시드 |
| 안동 구시장 | lively 0.90 | Lively 시드 |
| 월영교 야경 | romantic 0.92 | Romantic 시드 |
| 동네 골목길 | local 0.92 | Local 시드 |
| 안동 뷰 카페 | photogenic 0.85 | Photogenic 시드 |
| 병산서원 | relaxing 0.90 | Relaxing 시드 |
| 루프탑 카페 | modern 0.95 | Modern 시드 |

## 5. 온보딩 진행 흐름

```
앱 최초 실행
    ↓
GET /onboarding/status  ← 앱 재시작 시 진행 상태 복원
    ↓
GET /onboarding/next    ← 서버가 알고리즘으로 카드 선택
    ↓
사용자 좋아요 / 싫어요
    ↓
POST /onboarding/swipe  ← 벡터 업데이트
    ↓
종료 조건 체크
  ├── 수렴 완료 (변화량 < 0.03, 최소 15장) → POST /onboarding/complete
  ├── 최대 25장 도달 → POST /onboarding/complete
  └── 아직 진행 중 → GET /onboarding/next 반복
```

## 6. 카드 선택 알고리즘

### 단계 1 — 시드 카드 (첫 7장)

처음 7장은 태그별 대표 시드 카드를 순서대로 제공한다.
모든 태그에 대한 초기 정보를 확보하기 위한 단계이다.

```
시드 큐: [relaxing, lively, romantic, local, photogenic, traditional, modern]
→ 순서대로 각 태그의 대표 카드 1장씩 제공
```

### 단계 2 — 적응형 선택 (8장~)

시드 카드 소진 후 **균형 60% + 탐색 30% + 랜덤 10%** 혼합 전략으로 카드를 선택한다.

랜덤 10%는 v1.0.0 대비 신규 추가된 요소로, 사용자가 특정 패턴에 갇히는 것을 방지한다.

#### 균형 전략 (60%) — 부족한 태그 보완

```
현재 user_vector에서 점수가 낮은 태그 상위 3개 파악
→ 해당 태그가 강한 카드를 우선 선택

예시)
현재 벡터: relaxing 0.8, traditional 0.9, romantic 0.2, lively 0.1, modern 0.1
부족 태그: lively, modern, romantic
→ lively/modern/romantic 점수 합이 높은 카드 선택
```

#### 탐색 전략 (30%) — 유사 취향 확장

```
현재 user_vector와 후보 카드 벡터의 Cosine Similarity 계산
→ 유사도 높은 카드 선택 (좋아요한 것과 비슷한 분위기 탐색)

좋아요 0개일 때: 랜덤 선택으로 대체
```

#### 랜덤 전략 (10%) — 패턴 탈출

```
후보 카드 중 랜덤 선택
→ 사용자가 무의식적으로 비슷한 카드만 선택하는 패턴 방지
→ 예상치 못한 취향 발견 가능성 확보
```

#### Cosine Similarity 계산

```
similarity(user, card) = Σ(user[t] × card[t]) / (|user| × |card|)

|v| = √(Σ v[t]²)
```

### 중복 제거

이미 보여준 카드는 후보에서 제외한다.

## 7. 벡터 업데이트 알고리즘

### 핵심 원리 — 상대적 업데이트

카드의 **모든 태그를 올리는 것이 아니라**, 카드 내에서 강한 태그는 올리고 약한 태그는 내린다.
이를 통해 전부 좋아요를 눌러도 모든 태그가 100%가 되는 문제를 방지하고
결과 벡터가 **뾰족한 개성**을 갖도록 한다.

### 계산 방식

```
카드 벡터 평균 = Σ card[t] / 7

상대 점수[t] = card[t] - 카드 벡터 평균

좋아요:
  user[t] = user[t] + 상대 점수[t] × 0.40

싫어요:
  user[t] = user[t] - 상대 점수[t] × 0.25

범위 클램핑: 0.0 ≤ user[t] ≤ 1.0
정규화: 없음 (독립 관리)
```

### v1.0.0 대비 변경사항

| 항목 | v1.0.0 | v2.0.0 | 변경 이유 |
|------|--------|--------|-----------|
| 좋아요 학습률 | 0.25 | 0.40 | 결과가 50~75%에 몰리는 문제 해결 |
| 싫어요 학습률 | 0.12 | 0.25 | 배제 신호 강화 (좋아요의 60% 수준) |

### 업데이트 예시

하회마을 카드 (traditional 0.95, modern 0.05, relaxing 0.85, lively 0.10, romantic 0.30, local 0.60, photogenic 0.75)를 **좋아요** 시:

```
카드 평균 = (0.95+0.05+0.85+0.10+0.30+0.60+0.75) / 7 ≈ 0.514

traditional: 0.5 + (0.95 - 0.514) × 0.40 = 0.5 + 0.174 = 0.674  ↑↑
modern:      0.5 + (0.05 - 0.514) × 0.40 = 0.5 - 0.186 = 0.314  ↓↓
relaxing:    0.5 + (0.85 - 0.514) × 0.40 = 0.5 + 0.134 = 0.634  ↑
lively:      0.5 + (0.10 - 0.514) × 0.40 = 0.5 - 0.166 = 0.334  ↓
romantic:    0.5 + (0.30 - 0.514) × 0.40 = 0.5 - 0.086 = 0.414  ↓
local:       0.5 + (0.60 - 0.514) × 0.40 = 0.5 + 0.034 = 0.534  →
photogenic:  0.5 + (0.75 - 0.514) × 0.40 = 0.5 + 0.094 = 0.594  ↑
```

카드 하나로 traditional이 0.5 → 0.674까지 올라가고 modern은 0.314까지 내려간다.
뾰족한 취향 분리가 가능해진다.

### 여행 기록 업데이트 (온보딩 이후)

온보딩 이후에도 벡터는 서비스 이용에 따라 계속 업데이트된다.

| 행동 | 업데이트 방식 |
|------|--------------|
| 스와이프 like | 해당 장소 태그 상대적 +0.40 |
| 스와이프 must | 해당 장소 태그 상대적 +0.60 (강화) |
| 스와이프 skip | 해당 장소 태그 상대적 -0.25 |
| 여행 기록 작성 | AI 분석 태그 +0.15 |
| 좋아요 | 해당 장소 top_tags +0.10 |

## 8. 종료 조건

### 정상 종료 — 벡터 수렴

```
최근 3장의 벡터 변화량 평균 < 0.03  (v1.0.0의 0.05에서 강화)
AND 최소 15장 이상 진행              (v1.0.0의 12장에서 상향)

변화량 = Σ |user[t]_after - user[t]_before| / 7
```

수렴 기준을 0.05 → 0.03으로 낮추고 최소 장 수를 15장으로 올린 이유:
학습률이 높아진 만큼 변화량도 커지기 때문에 기준을 더 엄격하게 잡아야
충분한 정보 수집 후 종료된다.

### 강제 종료 — 최대 장 수

```
총 25장 도달 시 무조건 종료
```

### 예외 처리

```
좋아요 3개 미만이면 최소 15장까지 강제 진행
(취향 신호 부족으로 인한 편향 방지)
```

### 종료 후

```
POST /onboarding/complete 호출
→ has_onboarded = true
→ 최종 user_vector 저장
→ top_tags 3개 반환 (스와이프 화면 기본 mood_tags로 사용)
```

## 9. 취향 재분석 (마이페이지)

사용자가 마이페이지에서 취향을 다시 분석하고 싶을 때 사용한다.

```
POST /onboarding/reset 호출
→ user_vector 전체 0.5로 초기화
→ has_onboarded = false
→ 기존 좋아요, 기록, 코스는 삭제되지 않음
→ 온보딩 플로우 재시작
```

## 10. 마이페이지 취향 프로필 표시

온보딩 및 서비스 이용으로 누적된 벡터를 시각화하여 사용자에게 보여준다.

### 표시 방식

- **0.5를 중립 기준선**으로 설정
- 0.5 이상 → 선호 태그 (도형 바깥쪽)
- 0.5 미만 → 비선호 태그 (도형 안쪽)
- 7각형 레이더 차트로 표현

```
❌ v1.0.0: 모든 태그 0~100% 표시 → 전부 중간값에 몰려 개성 없음
✅ v2.0.0: 0.5 기준 중립선 기준으로 선호/비선호 명확히 구분
```

### 표시 예시

```
🌿 나의 여행 감성

😌 Relaxing      ████████░ 78%  ← 선호
📷 Photogenic    █████████ 89%  ← 강한 선호
🏘 Local         ███████░░ 69%  ← 선호
🏯 Traditional   █████████ 85%  ← 강한 선호
❤️ Romantic       ████░░░░░ 41%  ← 비선호
🎉 Lively        ███░░░░░░ 28%  ← 강한 비선호
🏙 Modern        ████░░░░░ 38%  ← 비선호

→ "조용하고 전통적인 공간, 사진 찍기 좋은 숨은 명소를 선호하는 여행자"
```

## 11. 구현 시 주의사항

**SSOT**: 태그 7개 목록은 DB `emotion_tag` 테이블이 원본.
클라이언트/AI 파트 모두 `GET /tags` API에서 가져올 것. 하드코딩 금지.

**상태 저장**: 온보딩 진행 중 user_preference 테이블에 매 스와이프마다 즉시 저장.
앱 종료 후 재시작 시 `GET /onboarding/status`로 복원.

**카드 벡터**: AI 파트가 사전에 모든 온보딩 카드 이미지를 분석하여 DB에 저장.
온보딩 런타임에 AI 호출 없음. 카드 풀은 태그별 최소 4장 이상 확보 필수.

**학습률 튜닝**: 현재 좋아요 0.40 / 싫어요 0.25는 시뮬레이션 기반 초기값.
실제 서비스 후 사용자 데이터 기반으로 조정 필요. 결과 벡터의 표준편차가
0.15 이상이 되는 것을 목표로 한다. (값이 낮으면 취향 분리 불충분)

**카드 풀 관리**: 온보딩 카드는 서비스 초기에 AI 파트가 일괄 분석하여 적재.
이후 신규 장소 추가 시 배치로 분석 및 풀 보충.
